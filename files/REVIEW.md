The baseline locks seroval 1.6.7 once. Four framework parents consume it: @tanstack/router-core 1.171.34, @tanstack/start-client-core 1.170.34, @tanstack/start-plugin-core 1.171.49, and @tanstack/start-server-core 1.169.39. Each installed package declares ^1.6.7. seroval-plugins 1.6.7 peers ^1.0. All accept the selected 1.8.1; no parent release or override is needed. The package's >=20 engine is compatible with pinned Node 22.20.0. Installed graph inspection found no second seroval version, and the nested mail lockfile has no seroval.

src/base/dispatch.ts routes /api/* to Hono and documents to Start. src/api.ts uses ordinary JSON parsing and authenticates workspace reads. src/server.ts dispatches document requests through Start, then src/workspace-document.ts inserts private workspace data as escaped application/json. No application createServerFn, createServerOnlyFn, createServerFileRoute, or custom seroval adapter was found. This reduces direct application exposure but is not a claim that all framework serialization paths are unreachable.

The installed Start server-function handler resolves function identities before fromJSON. Existing runtime core coverage exercises anonymous, forged, expired, valid and revoked document/API access and retained incident data. A separate bounded library probe tests the named dependency security properties directly and ordinary structured-data round trips.

The independent candidate review found no concrete surviving bypass or legitimate-behavior regression. The upgraded implementation obtains intrinsic typed-array names/accessors, uses an allowlisted constructor switch, obtains intrinsic RegExp source, requires real arrays for decoded collections, and accepts only genuine Stream/LiveStream instances as stream sources. Retained seroval-plugins 1.6.7 imports the upgraded isStream/createStream, and its ReadableStream deserializer checks isStream before invoking its stream factory. Thus retaining that plugin does not retain the reviewed source.on flaw.

Every seroval runtime API imported by current TanStack consumers remains exported: serialize, crossSerializeStream, getCrossReferenceHeader, createPlugin, createStream, fromJSON, fromCrossJSON, toJSONAsync, toCrossJSONAsync and toCrossJSONStream. Both ESM and CJS root entrypoints remain available. Request and response consumers resolve the same serializer.
