# Operating Oncall

README.md opens with the root command sequence. `describe` is authoritative for parser flags; `check` is structural, not a hosted health proof. `rer` provides the pinned Node and pnpm. SQLite/D1 is the relational store; .wrangler/state is canonical local data, .dev.vars contains private settings, .rer/local is local key custody. Never commit these.

The protected API retains held password accounts and adds Base email/dev identity for new installations. All private HTTP mutations require same-origin requests and current member/session authority. Ingress credentials are scoped to services and grant no private read access. /setup and /signin use Base native handlers; no private Start function exists.

Export/import use Base portability for the supported entire installation, including move-in records and journal. Base sessions, Oncall sessions and dev credentials are excluded; imported pending historical timers must remain paused and cannot resume because delivery is OFF. Restore requires an empty destination; use the separate protected checkpoint API for explicitly reviewed replacement. Retained third-party originals may contain personal data: keep archives private.

Actual deploy refuses. A dry run validates local build/declaration without provider requests. A hosted release needs a separately operated standby and conformant portable SQL binding before it can be approved. Never silently set LOCAL_ONLY=false or configure live mail/providers as part of this activation. The first hosted coordination scope must say how dual input, configuration pull and announcements work; paging additionally needs independently operated delivery channels and a real-phone drill.
